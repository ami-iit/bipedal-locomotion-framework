# Robot log format `v0.0.1`

This document specifies the format `v0.0.1` of the robot logs, i.e., the format of all the logs written before the introduction of the format version. It is written by the [`YarpRobotLoggerDevice`](../../README.md) of `bipedal-locomotion-framework` up to `v0.28.0`. A `.mat` file without the top-level `version` variable follows this format. See [README.md](./README.md) for the versioning of the format, and [v0.1.0.md](./v0.1.0.md) for the next format.

Most of the format is shared with `v0.1.0`. This document describes it completely, and highlights the differences with respect to `v0.1.0` with the **Difference** tag.

A log is composed of:
- a [`.mat` file](#the-mat-file) containing all the numerical and textual signals;
- optionally, one [video or image folder](#videos-and-images) per camera stream, in the same folder of the `.mat` file.

## File names
All the files of a log share the same base name `<prefix>_<YYYY>_<MM>_<DD>_<hh>_<mm>_<ss>`, where the date is the local time of the save, and `<prefix>` is `robot_logger_device`, or `robot_logger_device_<tag>` if the recording is saved with a tag.

| File | Content |
|:---|:---|
| `<base>.mat` | [The mat file](#the-mat-file). |
| `<base>_<camera>_rgb.mp4` | Color images of the camera `<camera>` (save mode `video`). |
| `<base>_<camera>_depth.mp4` | Depth images of the camera `<camera>` (save mode `video`). |
| `<base>_<camera>_<rgb\|depth>/img_<k>.png` | Images of the camera `<camera>` (save mode `frame`). |
| `<base>_<signal>_rgb/img_<k>.png` | Images of the exogenous image signal `<signal>`. |
| `<base>_*.txt` | Output of the `code_status_cmds` commands, if configured. |

When the logger saves the data periodically, every save produces a new `.mat` file together with its own videos and image folders. While recording, the images are written in files named `output_<camera>_<rgb|depth>[.mp4]` in the working directory of the logger, and they are renamed when the log is saved.

## The mat file
The file is a MATLAB `v7.3` file, i.e., an HDF5 file.

### Top-level variables
| Variable | Type | Content |
|:---|:---|:---|
| `<prefix>` | struct | [Root struct](#root-struct) of the log, named as the `<prefix>` of the [file name](#file-names) (`robot_logger_device` unless the log has been saved with a tag). |

**Difference:** the `version` variable is not present.

### Root struct
| Field | Type | Content |
|:---|:---|:---|
| `yarp_robot_name` | char array | Value of the `YARP_ROBOT_NAME` environment variable of the machine running the logger, e.g., `ergoCubSN001`. Empty if the variable is not set. |
| `description_list` | `n x 1` cell array of char arrays | Names of the logged joints, in the order used by all the joint channels. Present only if the robot data is logged. |
| other fields | struct | The [channels](#channels), organized in a tree. |

**Difference:** `yarp_robot_name` is the name of a robot, not a URI of the robot model. A reader can look for a model with this name (e.g., a folder `<yarp_robot_name>` containing a `.urdf` file in the folders listed in `GAZEBO_MODEL_PATH`, `ROS_PACKAGE_PATH` or `AMENT_PREFIX_PATH`), but the name is not guaranteed to identify a model.

### Channels
The channels have the same structure of `v0.1.0`. The name of a channel is a list of keys separated by `::`, stored as nested structs (e.g. `robot_logger_device.joints_state.positions`). Each leaf is a struct with the following fields, where `N` is the number of samples:

| Field | Type | Content |
|:---|:---|:---|
| `data` | see below | The samples. |
| `timestamps` | `N x 1` double | Time of each sample in seconds, read from the YARP clock. |
| `dimensions` | `3 x 1` uint64 | Size of `data`, e.g. `[n; 1; N]`. |
| `elements_names` | `1 x n` cell array of char arrays | Name of each element, `element_0`, `element_1`, ... if not provided. |
| `units_of_measure` | `1 x n` cell array of char arrays | Always `n.d.`. |
| `name` | char array | Last key of the channel name. |

| Channel type | `data` |
|:---|:---|
| vector of size `n` | `n x 1 x N` double array (`h5py` returns an array of shape `(N, 1, n)`). |
| image index | `1 x 1 x N` uint32 array. |
| string | `1 x N` cell array of char arrays. |
| text log | `1 x N` struct array. |

The channels do not share the time axis, and a channel without samples is stored as a struct without fields.

#### Robot, frames and text logging
The robot channels (`joints_state::*`, `motors_state::*`, `PIDs`, `FTs::<sensor>`, `gyros::<sensor>`, `accelerometers::<sensor>`, `orientations::<sensor>`, `magnetometers::<sensor>`, `cartesian_wrenches::<name>`, `temperatures::<sensor>`, `batteries::<battery>`), the frames channels (`frames::<parent>::<frame>::position` and `frames::<parent>::<frame>::orientation`) and the text logging channels (`<system>::<prefix>::<process>::p<pid>`) have the same names, elements and content of [`v0.1.0`](./v0.1.0.md#robot).

#### Exogenous signals
| Input type | Channel | Content |
|:---|:---|:---|
| `vectors_collection_exogenous_inputs` | `<signal>::<key>` | One vector channel for each key of the `VectorsCollection`, with the elements names provided by the metadata. |
| `vectors_exogenous_inputs` | `<signal>` | Vector channel with elements `element_<i>`. |
| `string_exogenous_inputs` | `<signal>` | String channel containing the content of the received bottles. |
| `human_state_exogenous_inputs`, `wearable_targets_exogenous_inputs`, `wearable_data_exogenous_inputs` | `<signal>::...` | Vector channels obtained by converting the `trintrin` messages. |
| `image_exogenous_inputs` | `exogenous_images::<signal>::rgb` | Image index channel, the images are stored in the folder `<base>_<signal>_rgb`. |

**Difference:** the `exogenous_signals_connection_id::<signal>` and `<channel>_connection_<k>` channels are not present.

#### Cameras
| Channel | Elements | Cameras |
|:---|:---|:---|
| `camera::<camera>::rgb` | `frame_index` | rgb and rgbd cameras |
| `camera::<camera>::depth` | `frame_index` | rgbd cameras |

In the frame mode, a sample `(timestamps(k), data(1, 1, k))` states that the image `img_<data(1, 1, k)>.png` has been acquired at time `timestamps(k)`. The index restarts from zero in each file.

**Difference:** in the video mode the camera channels are created but they do not contain samples, so the time of the images in the videos is not stored.

## Videos and images
| Stream | Save mode `video` | Save mode `frame` |
|:---|:---|:---|
| color | `<base>_<camera>_rgb.mp4`, written with the OpenCV `VideoWriter` using the codec `video_codec_code` (FourCC, default `mp4v`). | `<base>_<camera>_rgb/img_<k>.png`, 8 bit color. |
| depth | `<base>_<camera>_depth.mp4`, 8 bit grayscale, same codec of the color video. | `<base>_<camera>_depth/img_<k>.png`, 16 bit grayscale. |

- **Depth values.** The depth images contain the depth in meters multiplied by `rgbd_cameras_depth_scale`. In the frame mode the values are saturated to `uint16`, in the video mode they are saturated to `uint8` (e.g., with a scale of `1000` all the depths larger than `0.255 m` are saturated) and lossy compressed, so the depth videos are not suitable for a quantitative analysis.
- **Time.** **Difference:** the videos have a constant frame rate equal to the `fps` of the camera. An image is written every `1/fps` seconds of the logger clock, and the previous image is written again if a new one is not available. The first image is written when the recording starts, or after the previous save, so a video approximately spans the time of the `.mat` file. The images of the exogenous image signals are saved only when they arrive.

## Real-time streaming
As in `v0.1.0`, the vector channels can be streamed on the port `<port_prefix>/rt_logging` with the keys `robot_realtime::<channel>`, and the metadata contain `robot_realtime::yarp_robot_name` (**Difference:** the value of `YARP_ROBOT_NAME`), `robot_realtime::description_list` and `robot_realtime::timestamps`.

## Visualization with `robot-log-visualizer`
The [`robot-log-visualizer`](https://github.com/gbionics/robot-log-visualizer) considers a file without `version` as a `v0.0.1` log:

- **Robot model.** Since `yarp_robot_name` is not a URI, the model is not loaded automatically. It can be loaded by setting the model and the package folder manually before opening the file.
- **Videos.** The `<base>_*.mp4` files are opened in a tab. Since the camera channels are empty, each video is assumed to span the entire log, and it is synchronized proportionally to the position in the log. The depth videos are shown as grayscale videos.
- **Images streamed as numerical signals** are displayed as in [`v0.1.0`](./v0.1.0.md#visualization-with-robot-log-visualizer).

## Logs created before `bipedal-locomotion-framework` `v0.7.0`
The logs created by `bipedal-locomotion-framework` `v0.6.0` do not have a valid `yarp_robot_name` field and `elements_names` of the `joints_state` and `motors_state` channels. They were converted to the `v0.0.1` format by the [`migrate_0_6_0_to_0_7_0.m`](https://github.com/gbionics/bipedal-locomotion-framework/blob/v0.28.0/devices/YarpRobotLoggerDevice/scripts/migrate_0_6_0_to_0_7_0.m) script, which is available up to `v0.28.0`.
